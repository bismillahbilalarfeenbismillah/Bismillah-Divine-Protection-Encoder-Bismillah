# Bayyinah Collected Works x EESS: Independent Corpus Network

**What this is:** A source- and proposal-linked semantic knowledge graph derived from the October 25, 2026 Bayyinah Collected Works and Master Differentiator Strategy release, compared with the previous Build It Yourself corpus network.

**What this is NOT:** A trained neural network, proof of the source works' conclusions, certification that an EESS instrument already implements the proposed design, a trusted external signature, or authorization to modify repository code.

## Start here

1. Open `Bismillah_Interactive_Corpus_Network.html` in a local browser. No external scripts or network requests are needed. Search P IDs or concepts; a matching node plus first-degree neighbors is shown. Click nodes to read relationship types and source provenance. Zoom with mouse wheel and pan by dragging. Use source-type toggles to show previous-pack docs, domain adapters, and the legacy archive index node.
2. Read `Bismillah_Corpus_Development_Analysis.md` for the executive conclusions, twelve proposed product epics, source anchors, instrument role assignments, threat boundaries and Gate 4 questions.
3. Load `Bismillah_Corpus_Knowledge_Network.json` or `.graphml` into another LLM or graph tool for further analysis. CSV node/edge tables and source/evidence indexes are also provided.
4. Examine `Bismillah_EESS_Claim_Receipt_v0_1_DRAFT.schema.json` and the illustrative EXAMPLE JSON as a **draft** to challenge, not an adopted Shahid or HABL protocol.

## Inventory and integrity observations

- Outer archive: 40 entries (15 substantive payloads + 25 sidecars).
- Nested update kit: 173 files; catalog: **79** included primary works, from an 81-item inventory with two documented exclusions (P035 private-conversation/code-history; P048 byte duplicate).
- Original source bytes: **79/79 included originals match inventory SHA-256**. The two excluded entries are absent by editorial design.
- Strategy source registry: **112** source records; historical appendix index: **995** navigation records, not independent empirical validations.
- Outer release manifest: **35/35** listed files hash-match.
- Exactly **3** current artifacts (Collected Works Markdown/PDF and Master Strategy PDF) are byte-identical to their equivalents in the previous uploaded pack.
- Graph: **137 nodes, 662 typed edges**, including 79 source-work nodes, 14 method themes, 6 EESS instruments, 12 product/design candidates, 8 illustrative sectors, and 15 previous-pack reference nodes.

SHA-256 comparison is internal byte consistency; an attacker replacing both content and its unsigned manifest could defeat that evidence. Thematic links and source citations are not independent corroboration. The source corpus contains theological and speculative works; this graph does not assert their speculative mechanisms as observed technical facts.

## Data provenance and privacy

The original large corpus and full human conversations were **not** repackaged here. The graph includes selected bibliographic metadata, titles, short introductory snippets, source identifiers, hashes, and short human-authored technical summaries. One contact email found in a source introduction was redacted from the exported graph. The historical 995 records are exported **as an index only**, not as copied text bodies. Please review title-level records and source distribution rights before public publication.

No source scripts were executed. No GitHub repositories, pull requests, or governance gates were changed. The document graph refers to the six instruments by name and earlier reported design state; it is **not** a fresh independent code audit of those repos.

## Relationship semantics

- `explicit_source_citation`: master Strategy literally cites a P ID.
- `topic_mention`: a capped term-pattern match in one selected work.
- `lexical_similarity`: TF-IDF proximity on sampled work text, for exploration only.
- `source_inspiration`: source study is relevant to an engineering idea, which remains hypothetical.
- `instrument_dependency`: potential implementation role; no present-day feature is implied.
- `part_of_collection`: inventory membership, not independent validation.
- `byte_identical`: exact file match, and therefore **not a new witness**.
- `prior_pack_theme`: previous graph metadata, not reanalyzed source content.
